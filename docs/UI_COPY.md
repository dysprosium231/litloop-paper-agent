# 界面文案规范

LitLoop 桌面 app 里给用户看的文字都按这份写。

## 0 范围和用法

**管哪些文字**

- 前端：`app/src/**/*.tsx` 里的页面、按钮、提示、`aria-label`、`title`、`placeholder`。
- 后台返回给 app 显示的文字：
  - `src/litloop/app_settings.py`：设置项的 `title` / `label` / `help` / `placeholder` / 选项名，检测结果，代理设置引导；
  - `src/litloop/proxy_check.py`：代理软件名、引导里出现的程序名；
  - `src/litloop/app_server.py`：返回给 app 的错误；
  - `src/litloop/download_jobs.py`：任务标题、条目的 `error`；
  - `src/litloop/rename.py` 的 `FORMATS`：文件名格式的名称。
- 不管：代码注释、日志、CLI 和 MCP 工具的输出（它们给 Agent 和开发者看）。

**写一条新文案的步骤**

1. 查[术语表](#5-术语表)，用表里的叫法。
2. 在[组件写法](#6-组件写法)里找到对应的组件，照句式写。
3. 对照[排版与标点](#4-排版与标点)和[长度上限](#8-长度上限)。
4. 跑 `cd app && npm run lint:copy`（见[工具检查](#10-工具检查)）。
5. 按[自查清单](#9-自查清单)过一遍。

## 1 原则

1. **以用户为主体**：说用户能做什么、得到什么，不说系统做了什么。〔Ant 文案〕
   - 好：`下载完成的文献将显示在此处`
   - 不好：`系统会在下载任务结束后把记录写入推送队列`
2. **短**：去掉不带信息的字，不重复用户已知的事。〔Ant 文案〕〔微软 2.1.1〕
   - 好：`3 篇已推送`；不好：`全部 3 篇文献都已经成功推送完成`
3. **用用户熟悉的词**：不用内部字段名、英文代号。〔Ant 文案〕
   - 好：`未找到开放获取版本`；不好：`fast lane failed (no OA url / API miss)`
4. **一致**：同一个东西始终一个叫法（见术语表）；入口名和点开后的页面标题一致。〔Ant 文案〕
   - 左栏「下载」→ 页面标题「下载」；按钮「推送到 Zotero」→ 进度「正在推送到「LitLoop/…」」。
5. **重要的放前面**：结论在前，原因和办法在后。〔Ant 文案〕
   - 好：`无法下载：学校未订阅此期刊`；不好：`由于学校没有订阅此期刊，所以无法下载`
6. **说清下一步**：出错时说怎么办；做之前说清做完得到什么。〔Ant 文案〕
7. **具体**：时间、数量写具体值，不用“近期”“一些”“稍后”这类含糊词。〔Ant 文案〕
   - 好：`重置 10-18 08:00`；不好：`稍后重置`

## 2 语气

**整体**：清楚、友好、简洁，像同事之间说话，不像公文。〔微软 2.1〕不用网络用语和过度口语（“亲”“哦”“~”“搞定啦”）。〔微软 4.1.8〕〔Ant 文案〕

**称呼**

- 称用户为“你”，不用“您”。能省掉代词就省掉。〔Ant 文案〕〔微软 4.1.12〕
  - 好：`你改了 3 篇的评分`；更好（不影响意思时）：`已修改 3 篇的评分`
- 同一句里不混用“你”和“我”。〔Ant 文案〕标签里表示“用户自己的”可以用“我的”（「我的评分」），但同一区域的句子不要再出现“你的评分”。
- app 不自称“我们”。需要主语时写“LitLoop”：`LitLoop 会自动直连，无需设置`。〔Ant 文案〕只在用户反馈、申诉类场景允许“我们”，LitLoop 没有这类场景。
- Agent 是另一个角色，写“Agent”：`Agent 的评分`、`Agent 尚未评分`。

**“请”**

- 只用在需要用户动手的地方，一句最多一个：`Zotero 未运行，请先启动 Zotero。`
- 步骤、说明、按钮里不加“请”：`打开「路由设置」，新建一条规则。`
- 不用命令口吻的“不能”“不要”“请勿”，改说怎样做才对。〔Ant 文案〕
  - 好：`只填学校提供的代理地址，个人代理软件的端口会导致机构下载失败`
  - 不好：`个人翻墙代理不要填`

**“抱歉”**

- 只在问题出在 LitLoop 自己时用，用户造成的情况不用。用“抱歉”，不用“对不起”。〔Ant 文案〕
  - 用：`抱歉，下载时出现意外错误。详情已写入日志`
  - 不用：`抱歉，Key 无效`（Key 是用户填的）

**不责怪、不吓人**

- 出错时说现状和办法，不指责用户。〔Ant 文案〕
  - 好：`Key 无效（HTTP 401）。在 Elsevier 开发者网站核对后重新填写`；不好：`你填写的 Key 是错的`
- 不用“绝不”“永远”“最好”“唯一”这类绝对化说法。〔Ant 文案〕〔微软 4.1.3〕
- 感叹号只用于问候和祝贺，界面里基本不用。〔Ant 文案〕

**看人说话**：同一件事，面对新手和熟悉代理软件的用户可以写得不同。〔Ant 文案〕网络页的引导默认读者不熟悉代理软件，步骤写到点哪个按钮。

## 3 用词

| 用 | 不用 | 出处 |
|---|---|---|
| 其他 | 其它 | 〔Ant 文案〕 |
| 此（此期刊、此分类） | 该 | 〔Ant 文案〕 |
| 登录 | 登陆 | 〔Ant 文案〕 |
| 抱歉 | 对不起 | 〔Ant 文案〕 |
| 如果、要 | 倘若、假使、若要 | 〔微软 2.1.2〕 |
| 只是 | 仅是 | 〔微软 2.1.2〕 |
| 到（添加到、推送到） | 至 | 〔微软 4.1.5〕；用户 2026-10-17 确认用“推送到” |
| 但、总之 | 但是、总而言之 | 〔微软 4.1.6〕 |
| 文件名、程序名、用户名 | 文件名称、程序名称 | 〔微软 2.1.3〕 |
| 上限、下限 | 最大限制、最低限制 | 〔微软 2.1.3〕 |
| 选择（在说明里描述操作） | 点击、单击 | 〔微软 3.2〕 |
| 正在下载… | 下载中…（动态提示里） | 〔微软 4.1.15〕 |
| 和、外加、关于 | &、+、~（在句子里代替词） | 〔微软 3.2〕 |
| 无法连接 | 连不上 | 〔Ant 文案〕不过度口语化 |

- 量词用具体的，少用“个”：文献“篇”、检索会话和下载任务“个”、规则“条”、批次“批”、请求“次”。〔微软 4.1.10〕
- 少用“的”，能省就省：`下载完自动推送`，不写 `下载完成的时候自动进行推送`。〔微软 4.1.3〕
- 用简单现在时，不写“将会”，除非真是以后才发生：`不存在的分类会自动创建`。〔微软 4.1.15〕
- 可以用短句、省略句：`步骤如下：`。〔微软 4.1.14〕

## 4 排版与标点

### 4.1 空格

- 中文与英文之间、中文与数字之间加一个半角空格：`Zotero 运行中`、`共 3 篇`。〔指北〕〔Ant 文案〕
- 数字与英文单位之间加空格：`120 GB`、`30 MB`。〔指北〕
- 数字与 `%`、`°` 之间不加：`15%`。〔指北〕
- 数字与中文量词、单位之间同样加空格：`3 篇`、`1 次`、`9,800 积分`。〔指北〕〔Ant 文案〕
- 全角标点与任何字符之间不加空格：`推送到「LitLoop」`、`Key 无效（HTTP 401）`。〔指北〕
- 文字链与前后中文之间加空格：`未填写 Key。 申请`。〔Ant 文案〕〔指北〕（指北列为两可，本项目加）
- JSX 里插值两边的空格要写进字符串：`` `已完成 ${done} · 共 ${total}` ``。CSS 不会自动补。〔指北〕

### 4.2 标点总则

- 中文句子里用全角标点：，。：；？！「」（）、。〔指北〕
- 不叠用标点：不写 `！！`、`？？`。〔指北〕
- 引用整句英文时，句内用英文标点；代码、规则、配置项照原样用等宽字体：`find-process-mode: always`、`PROCESS-NAME,python.exe,DIRECT`。〔指北〕
- 并列的词用顿号：`Sci-Hub、LibGen 等`。〔微软 4.1.13〕
- 不用破折号 `——`，它在界面里像“一”。改用括号、冒号或改写。〔微软 4.1.13〕
- 隐藏内容用 `•` 或 `…`：Key 显示为 `sk-a…9f3c`；完全隐藏用 `••••••••`。〔Ant 文案〕建议用 `*`，本项目沿用已有的 `•`。

### 4.3 句末标点

| 元素 | 句末标点 |
|---|---|
| 按钮、链接、标题、标签、菜单项、选项、徽标、状态值 | 不加〔Ant 文案〕 |
| 输入框下的说明、悬停提示、表格里的单句、状态行、空状态 | 不加〔Ant 文案〕 |
| 检测结果的状态短语：`可用`、`未填写`、`Key 无效（HTTP 401）` | 不加 |
| 提示框、对话框正文、引导步骤、详情页里的说明句 | 加句号 |
| 两句及以上的任何文字 | 每句都加句号〔Ant 文案〕 |
| 说明句后面紧跟一个文字链 | 说明句加句号，文字链不加〔Ant 文案〕 |
| 列表里的完整句子 | 加句号〔Ant 文案〕 |

### 4.4 引号

- 一律用「」，嵌套用『』。不用 `“”`、`‘’` 和半角 `"`。
- 用在：界面元素名（`在「前置规则」中添加`）、用户要说或要输入的话（`回到对话说「继续」`）、动态插入的名字（`正在推送到「LitLoop/钙钛矿稳定性」`）。
- 不用在：产品名（`Zotero`）、按键（`按 Enter`〔微软 4.1.7〕）、等宽字体显示的代码。

### 4.5 冒号、括号

- 冒号用全角 `：`，后面不加空格：`来源：MDPI`、`快捷键：↑↓ 切换`。
- 括号用全角 `（）`，里面是中文还是英文、数字都一样：`重试未完成项（2）`、`Key 无效（HTTP 403）`。〔指北〕
- 括号里不放必须读的信息；用户一定要知道的写进正文。

### 4.6 省略号

- 用单个字符 `…`（U+2026），不用 `...` 或 `……`。〔Ant 文案〕
- 用在：进行中的动作（`正在加载…`）、截断的文本（`钙钛矿太阳能电池的…`）、路径中省略的部分（`LitLoop/…`）。
- 按钮打开新窗口或需要再选一步时，按钮名不加 `…`。

### 4.7 斜杠、箭头、分隔点、连接号

| 符号 | 用法 | 例 |
|---|---|---|
| `/` | Zotero 分类路径、分数、“已完成数/总数” | `LitLoop/钙钛矿`、`3/6`、`9,800 / 10,000 积分` |
| `→` | 界面导航路径，两边各一个空格，整条放在一对「」里 | `在「设置 → 学校认证」中登录` |
| ` · ` | 状态行里分隔短项，两边各一个空格 | `进行中 · 3/6 · 10-17 10:15` |
| `–` | 数字、时间范围，两边不加空格 | `1–4 评分`、`10:15–10:21` |
| `-` | 日期 | `2026-10-17`〔Ant 文案〕 |

- 句子里表示“或”时写“或”或用顿号，不用斜杠：`不再登录 WebVPN 或 CARSI`。标签里的紧凑写法可以用斜杠表示二选一或并列，两边不加空格：`高/中/低/不相关`。〔微软 4.1.13〕
- 时间先后不用 `→`（它专指导航）：写 `10:15–10:21`，不写 `10:15 → 10:21`。
- 两个数的“剩余 / 上限”在数字之间用 ` / `（两边加空格），“已完成数/总数”这种紧凑计数不加：`3/6`。

### 4.8 数字

- 一律用半角阿拉伯数字：`3 篇`，不写 `三篇`、`３ 篇`。〔Ant 文案〕〔指北〕
- 五位及以上加千位分隔符（`toLocaleString()`）：`12,480 篇`、`9,800 积分`；四位及以下不加：`2024`、`1500 篇`。
- 小数只在有意义时保留，空间大小取整：`剩余 120 GB`。
- 数字后面跟量词：`3 篇`、`2 个检索会话`；不写光秃秃的 `已推送 3`，除非在 ` · ` 状态行里且前面的词已说明对象。〔微软 5.5.2〕
- 版本号：`版本 0.4.2`。〔微软 5.2〕
- 不显示 `0 秒`、`NaN`、`undefined`、`?`：没有值时省掉这一项，或写 `—`（只用于表格单元格）。

### 4.9 单位

| 量 | 单位 | 例 |
|---|---|---|
| 文献 | 篇 | `共 6 篇` |
| 检索会话、下载任务、程序 | 个 | `2 个检索会话` |
| 批次 | 批 | `第 3 批` |
| OpenAlex 额度 | 积分（官方单位 credits） | `今日剩余 9,800 / 10,000 积分` |
| Elsevier、Springer Nature 额度 | 次（按请求计） | `本周剩余 19,990 次` |
| 被限流 | 次 | `被限流 2 次` |
| 磁盘空间、文件大小 | KB、MB、GB | `剩余 120 GB` |
| 时长 | 秒、分、小时 | `1 分 20 秒` |

额度的上限、重置周期以 [docs/API_LIMITS.md](API_LIMITS.md) 为准，界面里不写自己推算的数。

### 4.10 日期、时间、时长

- 完整：`2026-10-17 10:15`（年月日用 `-`，〔Ant 文案〕）。秒只在日志里显示。
- 列表里当年的日期省年份：`10-17 10:15`。跨年的仍写全。
- 同一天的起止：`10-17 10:15–10:21`；跨天：`10-17 23:50–10-18 00:10`。
- 时长：不到 1 分写 `45 秒`；不到 1 小时写 `1 分 20 秒`；更长写 `1 小时 5 分`（去掉秒）。
- 星期写 `周一`…`周日`。〔微软 4.1.1〕
- 少用相对时间（“刚刚”“3 分钟前”）；要用时只用于 1 小时内，超过就写绝对时间。时间信息要具体〔Ant 文案〕。

### 4.11 中英混排、大小写

- 专有名词照官方写法，不改大小写，不自造缩写。〔指北〕〔Ant 文案〕〔微软 4.1.1〕
- 缩写词全大写：`DOI`、`PDF`、`HTTP`、`TUN`。〔Ant 文案〕〔微软 4.1.2〕
- 英文缩写在中文里不加复数 s：`API Key`，不写 `API Keys`。〔微软 4.1.2〕
- 产品名不缩写：`Windows`，不写 `Win`。〔微软 4.1.1〕
- 能翻译成通用中文的就用中文：`分类` 而不是 `collection`，`直连` 而不是 `DIRECT`（引导里要用户照抄的规则除外）。
- 显示内部值时（如出站名 `direct`），在「」或等宽字体里照原样写，大小写不改。

### 4.12 专有名词

| 写法 | 不写 |
|---|---|
| LitLoop | Litloop、litloop、LITLOOP |
| Zotero、zotero-mcp | zotero、Zotero MCP、zotero mcp |
| OpenAlex、Scopus、ScienceDirect、Elsevier | Openalex、scopus、Science Direct |
| Springer Nature、Meta API | Springer、springer nature、MetaAPI |
| Crossref、CORE、Semantic Scholar、Unpaywall、arXiv | CrossRef、Core、arxiv、ArXiv |
| Sci-Hub、LibGen | SciHub、scihub、Libgen |
| WebVPN、CARSI、EZProxy | webvpn、WebVpn、Carsi、EZproxy |
| v2rayN、Clash Verge、mihomo、sing-box、Xray | V2rayN、clash verge、Mihomo、singbox |
| Chrome、Windows、macOS、Python | chrome、Win、MacOS、python |
| DOI、PDF、HTTP、TUN、IP、API Key | doi、pdf、Tun、api key、APIKey |

新出现的名称以对方官网首页的写法为准，补进这张表。

## 5 术语表

“不用”一栏的词不要出现在界面里。数量写法见 [4.9](#49-单位)。

**文献与检索**

| 用 | 不用 | 说明 |
|---|---|---|

## 6 组件写法

### 6.1 按钮

- 用动词或动宾短语，说清按下后发生什么，2–6 个字。〔Ant 按钮〕
  - 好：`开始下载`、`推送`、`更改分类`、`打开文件夹`、`检测`、`重试未完成项`
  - 不好：`确定`、`OK`、`点我推送`、`下载这 6 篇`、`去 Zotero`
- 数量放进状态行或括号：`重试未完成项（2）`。
- 一个按钮区最多一个主按钮；分不出主次时都用次按钮。〔Ant 按钮〕如下载队列每组的「开始下载」是主按钮，「打开文件夹」是次按钮。
- 顺序：用户最可能做的在前，有风险的在最后。〔Ant 按钮〕
- 切换类按钮写成下一步的动作，不写当前状态：已加入时显示 `移出下载`，已排除时显示 `取消排除`。
- 只有图标的按钮必须有悬停提示和 `aria-label`，内容是按钮名：`选择文件夹`、`收起侧栏`。〔Ant 按钮〕
- 按下后在原位变化的按钮，用过去式反馈 1–2 秒：`复制` → `已复制`；`保存` → 旁边显示 `已保存`。
- **危险按钮**（删除、清除、取消进行中的任务）：红色，写清对象：`清除`（Key 输入框旁）、`取消下载`。〔Ant 按钮〕不建议做的危险操作，把安全的那个设为主按钮。〔Ant 按钮〕
- **禁用按钮**：文案不变；在按钮旁或悬停提示里说为什么不能按：按钮「推送」禁用 + `当前有推送任务进行中`。不要只禁用不说明。
- 不用“取消”同时表示“关掉这个框”和“停止任务”：取消任务的确认框里，关掉的按钮写 `继续下载`。

### 6.2 文字链

- 文字说去哪里或做什么：`申请 Key`、`查看官方说明`；不写 `点击这里`、`链接`。
- 外部网站加外链图标；整句末尾的文字链不加句号。〔Ant 文案〕
- 说明里描述操作用“选择”或直接写动作，少用“点击”：`选择「编辑规则」`。〔微软 3.2〕

### 6.3 页面、区块标题

- 名词或名词短语，不加标点：`下载队列`、`推送队列`、`接口额度`、`学校认证`。
- 与进入它的导航项、按钮同名。〔Ant 文案〕
- 动态标题用内容本身：下载任务的标题就是检索问题，超长截断加 `…`。
- 重试产生的任务标题：`重试 · <原标题>`。

### 6.4 列表项和状态行

- 标题行放主体（文献标题、检索问题）；下面一行是 ` · ` 分隔的短项，不成句、不加句号。
- 顺序：状态 → 数量 → 来源/对象 → 时间。空的项整项去掉，不留多余的 ` · `。
  - 文献：`2024 · Nature Energy · 来源：MDPI`
  - 下载任务：`进行中 · 3/6 · 失败 1 · 10-17 10:15`
  - 推送记录：`新增 5 · 已存在 1 · 附件缺失 1`
  - 检索会话：`深度检索 · 已评分 120 · 10-17 09:40`
- 计数写在名词后：`失败 1`、`已存在 1`；整行开头作总结时写量词：`6 篇 · 2 个检索会话`。
- 状态行一行放不下就截断，完整内容放进悬停提示。

### 6.5 徽标

- 1–4 个字，不加标点：`高`、`中`、`低`、`不相关`、`待评`、`已修改`、`待下载`、`已撤稿`、`被引 128`。
- 颜色有固定含义：绿 = 高相关或成功；琥珀 = `中` 和需要注意；灰 = 低、不相关、待评；红 = 已撤稿和错误。琥珀色的 `中` 不表示警告。
- 一项一个徽标，最多两个并排；更多的放进详情。

### 6.6 字段式状态

- 写成 `对象：状态`，全角冒号，后面不空格：`Zotero：已添加`、`来源：MDPI`、`目标分类：LitLoop/钙钛矿稳定性`。
- 状态后要补原因时再加一个冒号，原因用短语：`Zotero：推送失败：未找到 zotero-mcp`。原因只放翻译后的话，原文进悬停提示（见第 7 节）。

### 6.7 表单：标签、占位文字、说明、校验

- **标签**：名词短语，不加冒号：`保存位置`、`文件名`、`联系邮箱`、`学校代号`。
- **开关的标签**：写打开后的效果，不写“是否”：`下载完自动推送`、`允许 Sci-Hub、LibGen 等来源`；不写 `是否自动推送`。
- **下拉选项**：同一组用同样的结构，选项互相不重叠：`开放获取优先`、`只用合法来源`、`Sci-Hub 优先`、`只用 Sci-Hub`。
- **占位文字**：给示例或格式，不重复标签，不放必须读的说明（输入后就消失）：`name@example.edu`、`buaa`、`留空自动查找`、`目标分类，以 / 分隔层级`。
- **说明**（输入框下）：只在填错会出问题时写，一句话，不加句号：`推送到「默认分类/检索问题」`、`可能违反出版商条款或学校规定，自行判断是否开启`。
- **来源提示**：值来自环境变量时，在值旁写 `来自环境变量`。
- **Key 类字段**：显示掩码；按钮 `填写` / `更换` / `清除`；输入框占位 `粘贴新的 Key`；未填时值显示 `未填写`。
- **校验**：紧挨着字段显示，不自动消失，用户改正后才消失。〔Ant 反馈〕〔Ant 消息〕说清怎样才对：
  - 好：`填写完整邮箱，例如 name@example.edu`
  - 不好：`格式错误`、`邮箱不合法！`
- 保存成功：在字段旁显示 `已保存`，几秒后消失；不弹窗。〔Ant 反馈〕简单操作效果可见时可以不反馈。

### 6.8 设置页的检测结果

每条结果 = 名称 + 图标 + 一句结果 + 可选的消耗说明。名称用服务名或设置项名：`OpenAlex`、`保存位置`、`代理软件`。

| 结果 | 图标 | 写法 | 例 |
|---|---|---|---|
| 可用 | 绿 ✓ | `可用` + 有用的余量 | `可用，今日剩余 9,800 / 10,000 积分`；`可写入，剩余 120 GB`；`v2rayN 以系统代理模式运行，LitLoop 会自动直连，无需设置` |
| 未配置、仅提示 | 灰 | `未填写 <什么>` + 不填的影响 | `未填写`；`未填写 Key，今日剩余 100 / 100 积分`；`未填写联系邮箱` |
| 无法使用 | 红 ✕ | `无法 + 动作：原因` 或 `<对象>无效（HTTP 码）` + 办法 | `Key 无效（HTTP 401）`；`无法连接 Crossref：连接超时`；`无法写入：没有此文件夹的写入权限` |

- 状态短语不加句号；后面跟了完整解释句，每句加句号：`已填写：LitLoop 会跳过学校登录。只填学校提供的代理地址。`
- 检测会消耗额度时说明：`（消耗 Scopus 1 次）`。
- HTTP 状态码放括号里，作为排查线索，不作为主要信息。
- 整组检测本身出错：`无法完成检测：<原因>`。

### 6.9 分步引导

用于代理软件设置这类要用户去别的程序里操作的场景（`app_settings.py` 的 `guides`）。

- 标题：`在 <程序> 中 <做什么>`：`在 v2rayN 中设置直连`、`在 Clash Verge 中设置直连`。
- 每步一个动作，动词开头，界面元素名放「」，句末加句号。
  - 好：`右键当前订阅，选择「编辑规则」。`
  - 不好：`你需要在 Clash Verge 里面找到规则设置的地方然后添加规则`
- 界面元素名照那个程序界面上的原文写（中文界面写中文，英文值照抄）：`出站选择「direct」`。
- 要用户照抄的内容放在复制块里，块的标签是名词：`程序名`、`规则`、`完整路径（填程序名不生效时使用）`。
- 编号由界面生成，文字里不写“第一步”“1.”。
- 最多 5 步；更多就拆成两个引导或链接到官方说明。
- 补充说明放在步骤后的 `note`，以条件开头：`如果规则未生效，在「扩展配置」中加入 find-process-mode: always。`〔微软 2.1.2〕
- 步骤依据对方官方文档写，在代码注释里留链接和核对日期。

### 6.10 进度和时间估计

- 超过 2 秒的操作要有加载提示；耗时长的显示进度和状态，并提供取消。〔Ant 反馈〕
- 主句：`正在 + 动词 + 对象`，不用“…中”。〔微软 4.1.15〕
  - `正在构建候选池`、`正在生成下一批`、`正在推送到「LitLoop/钙钛矿稳定性」`
- 副行（状态行）：`用时 1 分 20 秒 · 预计剩余 30 秒`、`已处理 3`、`正在处理：<文献标题>`。
- 阶段名用动宾短语，并列给出：`关键词`、`扩展候选池`、`补全摘要`、`排序`、`生成批次`。
- 预计剩余：
  - 算不出时不显示这一项，不写 `预计剩余 —`；
  - 剩余不到 1 秒或已计完、还在写结果时写 `即将完成`，不写 `0 秒`；
  - 不写“马上”“很快”。
- 页面级加载：`正在加载…`；知道在读什么时写具体对象：`正在读取设置…`。

### 6.11 提示：消息、提示框、通知

按严重程度和是否要用户处理选组件：〔Ant 反馈〕〔Ant 消息〕

| 级别 | 组件 | 是否自动消失 | 写法 | 例 |
|---|---|---|---|---|
| 成功（简单操作） | 原位文字或短消息 | 是，约 3 秒 | `已 + 动词`，不加句号 | `已保存`、`已复制` |
| 信息 | 页面内说明行 | 否 | 一句现状 | `当前有下载任务进行中。` |
| 警告（需要用户动手） | 琥珀色提示框 | 否 | 现状 + 办法，加句号 | `Zotero 未运行，请先启动 Zotero。` |
| 错误（这一处操作做不成） | 红色提示框或紧挨出错位置的文字 | 否 | 见第 7 节 | `无法读取 Zotero 分类：Zotero 未运行。启动 Zotero 后重试，或直接输入分类路径。` |
| 后台任务结束 | 通知 | 由用户关闭 | 结果 + 数量 | `下载任务已完成：6 篇中 5 篇已下载` |

- 重要的失败不用会自动消失的消息，要留在页面上并说明原因。〔Ant 反馈〕
- 能直接看到效果的简单操作不用提示（如切换评分）。〔Ant 反馈〕
- 一处只放一条提示；同一件事不要同时出现提示框和弹窗。
- 后台返回的冲突（409）也按这里写：`已有下载任务在进行，完成后再开始新的下载`。

### 6.12 确认

只在操作不能撤回或会丢掉进行中的工作时确认；能撤回的不确认。

- 轻量的用贴着按钮的气泡确认，重要的用对话框。〔Ant 反馈〕
- 标题问动作本身，用“此”指当前对象：`取消此下载任务？`、`清除 Elsevier Key？`
- 正文说后果，特别是会留下什么、会丢掉什么：`已下载的 4 篇会保留，其余 2 篇不再下载。`
- 按钮写动作本身，危险的那个红色：`取消任务` / `继续下载`；`清除` / `保留`。不用 `确定` / `取消`。〔Ant 按钮〕（Ant 默认是“确定 / 取消”，并说明可以优化）
- 不写 `你确定要…吗？`，直接问动作。

### 6.13 空状态

空状态要说明为什么空，并给出下一步。〔Ant 空状态〕一个标题 + 一行说明，都不加句号。

| 类型 | 写法 | 例 |
|---|---|---|
| 无数据（还没开始） | 标题：`暂无 + 对象`；说明：这里会出现什么、从哪儿来；可加一个文字按钮 | `暂无待下载文献` / `在筛选中加入下载的文献将显示在此处` + `前往筛选` |
| 完成或清空 | 只写结果，不加引导 | `已全部推送` |
| 搜索、筛选无结果 | `没有匹配的 + 对象`；可加 `清除搜索` | `没有匹配的设置`、`没有匹配的文献` |
| 未选择 | `选择 + 对象 + 以查看详情` | `选择文献以查看详情` |
| 缺字段 | `暂无 + 字段`，说明影响 | `暂无摘要，仅依据标题评分。` |

〔Ant 空状态〕不留空白页。

### 6.14 错误

见第 7 节。

### 6.15 快捷键提示

- 句子里的键名照微软写法：`Ctrl`、`Shift`、`Alt`、`Enter`、`Esc`、`Tab`、`Delete`、`空格键`、`向上键`、`向下键`；组合键用 `+`，不加空格：`Ctrl+Enter`。〔微软 5.5.4〕
- 有英文名的键后面不加“键”：`按 Enter`，不写 `按 Enter 键`。〔微软 5.5.4〕
- 列表底部的紧凑提示行可以用符号，格式 `快捷键：<键> <动作> · <键> <动作>`：`快捷键：↑↓ 切换 · 1–4 评分 · 空格 加入下载`。这一行要有完整的 `aria-label` 或可读文本。
- 动作名和按钮名一致：按钮叫「加入下载」，快捷键说明也写 `加入下载`。

### 6.16 悬停提示

- 只说明指向的对象，不放长段文字和可点的东西。〔Ant 反馈〕
- 用在：只有图标的按钮（写按钮名）、被截断的文字（写全文）、错误原文（供排查）、禁用按钮（写原因）。
- 一句话以内，不加句号。
- 不要把用户必须知道的信息只放在悬停提示里（触屏和键盘用户看不到）。

### 6.17 无障碍文本

- `aria-label` 和可见文字用同一套叫法：图标按钮 `收起侧栏`、分隔条 `调节列表宽度`、评分按钮组 `我的评分`。
- 图形要有文字替代：`每批高相关比例`。
- 不要用 `&`、`+`、`~` 代替词，读屏软件会读错。〔微软 3.2〕

## 7 错误信息

### 7.1 句式

```
无法 + 动作[：原因]。办法。
```

- 动作：用户刚才想做的事（下载、推送、连接 Crossref、写入保存位置）。〔微软 5.5.2〕把 Cannot / Unable to / Could not 统一译为“无法…”。
- 原因：用户能懂的话，一个短语；不知道原因就不写原因，不编。
- 办法：用户接下来能做的一件事，带具体位置（`在「设置 → 学校认证」中重新登录`）。没有办法时省掉，不写“请联系管理员”。
- 资源不足写 `<资源>不足，无法 + 动作`：`磁盘空间不足，无法保存 PDF`。〔微软 5.5.2〕
- 用户造成的不道歉；LitLoop 自身的意外错误开头加 `抱歉，`。〔Ant 文案〕

| 好 | 不好 |
|---|---|
| `无法下载：学校未订阅此期刊，或当前不在校园网。连接校园网或在「设置 → 学校认证」中登录后重试。` | `下载失败` |
| `无法推送：未找到 zotero-mcp。在「设置 → Zotero」中填写它的 Python 路径。` | `zotero-mcp not found` |
| `无法连接 Crossref：连接超时` | `连不上 Crossref：ReadTimeout(...)` |
| `抱歉，下载时出现意外错误。详情已写入日志。` | `KeyError: 'doi'` |

放进状态行或字段式状态时只留“原因”短语：`失败：学校未订阅` / `Zotero：推送失败：Zotero 未运行`。

### 7.2 原始错误的处理

下载引擎、zotero-mcp、各接口返回的原始错误多是英文或异常名，**不直接显示**。

1. 后台保留原文：任务文件里的 `error` 字段照旧存原文，供日志和排查。
2. 显示前翻译：在一处集中维护“原始错误 → 用户文字”的对照表，按错误码或稳定的前缀匹配，前端和后台都从这一处取，不在各组件里各写一份。
3. 匹配不到时，用通用句：`无法下载：出现意外错误`（或对应动作），原文放进悬停提示。
4. 原文截断到一行，不在界面主体里显示堆栈、异常类名、路径以外的内部字段。
5. 新增一类常见错误时，把它加进对照表和下面的样表。

对照样表（左列是现有代码里实际会出现的原文或前缀）：

| 原始错误 | 显示 |

## 8 长度上限

本项目约定，参考值，以界面不换行、不截断为准。〔Ant 空状态〕等来源未给字数限制。

| 元素 | 上限 |
|---|---|
| 按钮 | 6 个字（括号里的数量不算） |
| 徽标 | 4 个字 |
| 导航项、设置分组名 | 4 个字 |
| 页面、区块标题 | 10 个字（动态标题截断到一行） |
| 设置项标签 | 12 个字 |
| 输入框下的说明、悬停提示 | 1 句，30 个字 |
| 状态行 | 1 行，最多 5 项 |
| 提示框、检测结果的解释 | 2 句 |
| 错误信息 | 3 句（无法… / 原因 / 办法） |
| 空状态 | 标题 10 个字 + 说明 1 句 |
| 引导步骤 | 每步 1–2 句，最多 5 步 |

- [ ] 叫法都在术语表里，没有“不用”栏的词。

- [ ] 出错的地方有“无法 + 动作”和下一步；没有直接显示英文原文或异常名。
- [ ] 用“你”，没有“您”“我们”；同一句没有混用“你”“我”。
