# LitLoop 论文搜寻：纲领

> 2026-10-11 与维护者确认，2026-10-15 修订。这里只写目标、原则、验收标准和各阶段的设计要点；做到哪一步、下一步做什么，统一记在 [TODO.md](../TODO.md)。

## 用户痛点（按优先级）

1. **噪音多**：要翻很多页才能找到相关文章。
2. **看不过来**：人工筛选太累。
3. **不好判断文章质量**：期刊等级、引用、撤稿等信号不全。
4. **查不全**：做课题调研和综述时，靠几组检索词总会漏掉核心文章。阶段 1 解决了前三条之后，这是阶段 2 的重点。

中文文献“有更好，不急”。

## 原则

- **AI 给理由，人来决定**：AI 读摘要，标出相关程度并写一句理由；最终入选由用户确认，AI 不替用户排除文章。
- **结果可追溯**：保存检索词、数据源、时间和每篇的判断理由，下次可以接着搜，或只看新增。
- **筛选交给宿主 Agent**：相关性判断由运行插件的 Agent（如 Claude）完成，插件不另外调用大模型 API。插件内部需要排序时，只用不依赖外部服务的轻量方法。
- **宁可排后，不要删掉**：检索阶段对拿不准的结果只降低排名，不悄悄丢弃；确实要过滤的，在结果里说明过滤了多少、为什么。
- **用测试集说话**：改检索或排序之前，先用测试集确认问题存在；改完再用同一套测试集对比。

## 场景与验收标准

| 场景 | 验收标准 |
|---|---|
| A 快速查找 | 15 秒内出结果；前 10 条至少 8 条相关；每条有期刊等级、引用数、开放获取、撤稿标记和一句相关理由 |
| B 课题调研 | 从问题和几篇种子文章出发，主测试集的目标文章全部找到；能按主题分组呈现 |
| C 系统综述 | 记录每个数据源的检索量、去重数、纳入/排除数及理由（PRISMA 式）；可复查、可续跑 |
| D 定期追踪 | 只推送上次之后的新文章，不重复 |

### 测试集

放在 `tests/acceptance/`，每个 JSON 写明问题、种子、目标和来源；用户 Zotero 里对应的分类在「LitLoop 测试」下。目标文章由用户判断，不由 AI 生成。

| 角色 | 用途 |
|---|---|
| 主测试集（main） | 必须达标：目标全部找到 |
| 辅助测试集（auxiliary） | 只看召回率，例如以一篇综述引用的文献为答案 |
| 观察集（observe） | 目标分属多个子问题，只用来观察行为，不判定通过与否 |

评价深度检索时，比较“读到第 N 篇时找到了几篇目标”，而不只看最终是否找全：筛得越少就找全，越省用户的时间。

## 结果中每条记录应带的信息

标题、作者、年份、期刊、**期刊等级**、引用数、DOI、开放获取状态、**撤稿标记**、摘要、**相关度 + 理由**、数据源；一键进入下载队列和 Zotero 分类。

## 各阶段的设计要点

1. **阶段 1（降噪 + 质量信号，对应场景 A）**
   - 期刊等级由独立的私有工具 [litloop-journal-rank](https://github.com/dysprosium231/litloop-journal-rank) 提供（中科院分区、JCR、新锐分区、预警名单、CCF、用户自定义目录；ISSN 优先匹配），装了就自动标注，没装不影响检索。分区数据有版权，不进 LitLoop 公开仓库；对外开放前需改为由用户自行提供数据。
   - 撤稿与关注声明：优先读本机的 Retraction Watch 库并附原因，没有时用 OpenAlex 在线查。
   - 离题结果按匹配程度分档排序，不直接删除。
2. **阶段 2（深度检索，对应场景 B）**
   - 候选来源有两路：多组检索词各取较多原始候选；再加上和种子文章共同引用较多、且标题或摘要含核心词的文章（引用耦合）。只靠关键词会漏掉用词不同的文章，只靠引用会混进相邻课题，两路合并。
   - 分批交给 Agent 筛选，评为“高”的文章成为新种子继续扩展（滚雪球）。
   - 滚雪球容易被相邻课题带偏（信息检索里的查询漂移）。设计上要做到：
     - 同时利用相关和不相关的评分（持续主动学习，系统综述筛选的常用做法）；
     - 用户给的种子和原始检索词始终占固定权重；
     - 共同引用按文献的常见程度加权，避免种子变多后分数膨胀。
   - 很多文章在数据源里缺摘要，排序前要先补摘要；补不到的按“只有标题”单独判断，不能因此排到最后。
   - 何时停止由数据说明：最近几批几乎没有新的相关文章时建议停止，并报告必找文章的覆盖情况。
3. **阶段 3（系统综述，对应场景 C）**：检索记录与纳排理由落盘，PRISMA 统计，可续跑。
4. **阶段 4（追踪，对应场景 D）**：保存检索式，定期只看新增。
5. **之后**：中文文献（知网、万方）。
