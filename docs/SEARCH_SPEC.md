# LitLoop 论文搜寻：目标与路线

> 2026-10-11 与维护者确认。四种场景最终都要支持，分阶段实现。

## 用户痛点（按优先级）

1. **噪音多**：要翻很多页才能找到相关文章。
2. **看不过来**：人工筛选太累。
3. **不好判断文章质量**：期刊等级、引用、撤稿等信号不全。

查全率不是当前最大的痛点；中文文献“有更好，不急”。

## 原则

- **AI 给理由，人来决定**：AI 读摘要，标出相关程度并写一句理由；最终入选由用户确认，AI 不替用户排除文章。
- **结果可追溯**：保存检索词、数据源、时间和每篇的判断理由，下次可以接着搜，或只看新增。
- **筛选交给宿主 Agent**：相关性判断由运行插件的 Agent（如 Claude）完成，插件不另外调用大模型 API。

## 场景与验收标准

| 场景 | 验收标准 |
|---|---|
| A 快速查找 | 15 秒内出结果；前 10 条至少 8 条相关；每条有期刊等级、引用数、开放获取、撤稿标记和一句相关理由 |
| B 课题调研 | 多组检索词、多轮检索；领域核心文章（用户给出的 5–10 篇“必须出现”）全部覆盖；能按主题分组呈现 |
| C 系统综述 | 记录每个数据源的检索量、去重数、纳入/排除数及理由（PRISMA 式）；可复查、可续跑 |
| D 定期追踪 | 只推送上次之后的新文章，不重复 |

## 结果中每条记录应带的信息

标题、作者、年份、期刊、**期刊等级**、引用数、DOI、开放获取状态、**撤稿标记**、摘要、**相关度 + 理由**、数据源；一键进入下载队列和 Zotero 分类。

## 分阶段路线

1. **阶段 1（降噪 + 质量信号）**：期刊等级由独立的私有工具 [litloop-journal-rank](https://github.com/dysprosium231/litloop-journal-rank) 提供（中科院分区、JCR、新锐分区、预警名单、CCF、用户自定义目录；ISSN 优先匹配），装了就自动标注，没装不影响检索；撤稿与关注声明标记（优先读该工具下载到本机的 Retraction Watch 库，附原因；没有本地库时用 OpenAlex 在线查撤稿）；按等级过滤；结果精简输出带摘要；Agent 按“给理由、人决定”的方式标注相关度。对应场景 A。
   - 分区数据有版权，不进 LitLoop 公开仓库；对外开放前需改为由用户自行提供数据。
2. **阶段 2（深度检索）**：Agent 拆分多组英文检索词（中文提问自动转英文），插件并行检索、合并去重、记录轮次；沿核心文章的参考文献和施引文献扩展，直到新增很少。对应场景 B。
3. **阶段 3（系统综述）**：检索记录与纳排理由落盘，PRISMA 统计，可续跑。对应场景 C。
4. **阶段 4（追踪）**：保存检索式，定期只看新增。对应场景 D。
5. **之后**：中文文献（知网、万方）。

## 已完成（2026-10-11）

真实引用数、排序参数修复、按标题+摘要取高被引、离题结果过滤、年份筛选下推到数据源、摘要补全、交互检索约 14 秒。
